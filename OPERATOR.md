# Узел для другого оператора

Это не Python-хаб и не его форк. Процесс написан по `spec.md`, схемам и тест-векторам. Чужой человек забирает этот каталог, свой ключ и свой хост. Выключить узел может только тот, у кого процесс.

Узел делает федерацию каталога:

- читает `/.well-known` семян и проверяет подпись манифеста ключом из этого документа
- чужой узел остаётся в `observed_hubs` и не попадает в поиск
- в `peers` и в поиск попадают только те origin, которые оператор перечислил в `--admit`
- входящий `POST /ai-market/v2/federation/announce` не делает отправителя доверенным и не переписывает уже известного соседа
- адрес из частной сети, loopback и ссылка с управляющими символами не запрашиваются
- редиректы не следуют сами

Платежи, invoke и эскроу этот процесс не делает. Канал в спецификации переводит токены; здесь его нет нарочно.

```bash
cargo build --release --bin federator
./target/release/federator keygen --out operator.key
./target/release/federator serve \
  --key operator.key \
  --hub-url https://ИМЯ-ОПЕРАТОРА.example \
  --listen 127.0.0.1:8090 \
  --seed https://modelmarket.dev/.well-known/ai-market.json \
  --admit https://modelmarket.dev \
  --name "Имя оператора"
```

`--hub-url` — публичный адрес, которым оператор владеет. `--admit` повторяется для каждого origin, которому он согласен доверять каталог. Файл `operator.key` отдаётся следующему оператору вместе с командой запуска. В git его нет.
